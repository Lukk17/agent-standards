# Agent compatibility matrix

What each supported agent reads, where it reads it from, and the few places our layout has to work around a tool
limitation. Checked against the tools' official docs as of mid-2026, except where a cell says otherwise (the JetBrains
Copilot MCP path, for instance, is community-known rather than officially documented). This file stays in the
agent-standards repo only.

For the full repository tree and each agent's instruction-merge precedence, see
[repository-layout.md](repository-layout.md). For human MCP setup (keys, env vars, per-OS commands), see
[MCP_SETUP.md](MCP_SETUP.md).

---

### The one-paragraph version

Four of the five agents converged on two open standards: they read shared instructions from `AGENTS.md` and skills
from `.agents/skills/`, both natively, at the project root. Claude Code is the exception on both counts: it reads
`CLAUDE.md`, not `AGENTS.md`, and `.claude/skills/`, not `.agents/skills/`. That single gap is why the repo keeps a
`CLAUDE.md` that imports `AGENTS.md` and a `.claude/skills` symlink into `.agents/skills/`. Everything else (subagents,
preflight enforcement, MCP config) is per-tool because no shared format exists for those yet.

### Skills discovery

| Agent | Native project path | Native global path | Our solution |
| --- | --- | --- | --- |
| Claude Code | `.claude/skills/` | `~/.claude/skills/` | Symlink `.claude/skills/ -> ../.agents/skills/`; Claude Code does not read `.agents/skills/` |
| Kilo Code | `.agents/skills/`, `.kilo/skills/` | `~/.agents/skills/` | Reads `.agents/skills/` natively |
| OpenCode | `.agents/skills/`, `.opencode/skills/` | `~/.agents/skills/` | Reads `.agents/skills/` natively |
| Codex CLI | `.agents/skills/` | `~/.agents/skills/` | Reads `.agents/skills/` natively (scans cwd up to repo root) |
| GitHub Copilot | `.agents/skills/`, `.github/skills/`, `.claude/skills/` | `~/.agents/skills/`, `~/.copilot/skills/` | Reads `.agents/skills/` natively (VS Code, JetBrains, CLI, cloud agent) |

Only Claude Code needs a symlink. Every other agent reads the canonical `.agents/skills/` directly, which is why the
`.opencode/skills/` and `.codex/skills/` symlinks were removed.

### Instructions discovery

| Agent | Instruction file | How it loads |
| --- | --- | --- |
| Claude Code | `CLAUDE.md` | [.claude/CLAUDE.md](../.claude/CLAUDE.md) imports `@../AGENTS.md`; Claude Code does not read `AGENTS.md` natively |
| Kilo Code | `AGENTS.md`, `.kilocode/rules/` | Both auto-read from the project root every task |
| OpenCode | `AGENTS.md` | Auto-read from the project root (falls back to `CLAUDE.md`) |
| Codex CLI | `AGENTS.md` | Auto-read; walks nested `AGENTS.md` from root down to cwd, `AGENTS.override.md` wins at each level |
| GitHub Copilot | `AGENTS.md` | Read natively by the JetBrains plugin (since 1.6.1), VS Code agent mode, the CLI, and the cloud agent |

Copilot code review (the pull-request bot) and the IDEs that read only `.github/copilot-instructions.md` (Visual
Studio, Xcode, Eclipse) are out of scope; add that bridge per project if you target them. Plain VS Code Copilot chat
(not agent mode) also does not read `AGENTS.md`.

### Subagents discovery

| Agent | Native subagent path | Format |
| --- | --- | --- |
| Claude Code | `.claude/agents/` | Markdown |
| Kilo Code | `.kilocode/agents/` | OpenCode-format Markdown |
| OpenCode | `.opencode/agents/` | OpenCode-format Markdown |
| Codex CLI | `.codex/agents/` | TOML |
| GitHub Copilot | `.github/agents/` | `*.agent.md` (read by VS Code, JetBrains since 1.6.1, and the CLI) |

All five trees are generated by [../tools/gen_subagents.py](../tools/gen_subagents.py) from the one canonical
[../subagents/](../subagents/) source. No shared subagent format exists, so the generator fans one file out to five
per-tool trees. Never hand-edit the generated trees.

### Preflight enforcement

| Agent | Adapter | Mechanism | Cadence |
| --- | --- | --- | --- |
| Claude Code | [.claude/settings.json](../.claude/settings.json) | `UserPromptSubmit` hook (`additionalContext`) | every turn |
| Codex | [.codex/hooks.json](../.codex/hooks.json) | `UserPromptSubmit` hook (`additionalContext`) | every turn |
| OpenCode | [.opencode/plugin/preflight.js](../.opencode/plugin/preflight.js) | `chat.system.transform` plugin | every turn |
| Kilo Code | [.kilocode/rules/00-preflight.md](../.kilocode/rules/00-preflight.md) | rule loaded into context | every task |
| GitHub Copilot | [.github/hooks/preflight.json](../.github/hooks/preflight.json) | `sessionStart` hook (`additionalContext`) | once per session, CLI and cloud agent only |

Two limits shape the Copilot row. First, its `userPromptSubmitted` hook output is discarded, so per-turn injection is
impossible; only `sessionStart` can inject context, and only once. Second, hooks run on the Copilot CLI and the cloud
agent, not inside the VS Code or JetBrains IDE, so IDE users get the gate purely from `AGENTS.md`. Every adapter repeats
the same canonical wording from the `## Required opening move` section of `AGENTS.md`.

### MCP configuration

Split by surface, because several agents ship more than one client and the clients disagree on file and schema.

| Agent surface | Config file | Scope | Schema key | HTTP `type` | Env-var syntax | Template ships |
| --- | --- | --- | --- | --- | --- | --- |
| Claude Code | `.mcp.json` | project | `mcpServers` | `http` | `${VAR}`, `${VAR:-default}` | yes |
| OpenCode | `opencode.json` | project | `mcp` | `remote` | `{env:VAR}` | yes |
| Kilo Code (extension and CLI) | `.kilocode/kilo.jsonc` | project | `mcp` | `remote` | `{env:VAR}` | yes |
| Codex | `.codex/config.toml` | project (trusted) | `[mcp_servers]` | n/a (`command` or `url`) | none (literal) | yes |
| GitHub Copilot (VS Code) | `.vscode/mcp.json` | project | `servers` | `http` | `${env:VAR}`, `${input:NAME}` | yes |
| GitHub Copilot (JetBrains) | `~/.config/github-copilot/intellij/mcp.json` | global | `servers` | `url` (no `type`) | none documented | no |
| GitHub Copilot (CLI) | `~/.copilot/mcp-config.json` | global | `mcpServers` | `http` (or `sse`) | none (literal) | no |

The same eight servers are mirrored across every shipped template; only the file, schema key, `type` value, and
env-var syntax differ. Three surfaces get no template: the two global-only Copilot clients (JetBrains and CLI) have no
per-project MCP file, so a shipped `.example` would never be read. For those, copy the block from
[MCP_SETUP.md](MCP_SETUP.md) into the global file by hand. The Copilot CLI schema also requires a `tools` allowlist per
server (for example `"tools": ["*"]`) and does not interpolate `${VAR}`, so secrets go in literally and the file stays
out of version control.

### Per-agent caveats worth remembering

- Claude Code is the only agent that reads neither `AGENTS.md` nor `.agents/skills/` natively. Both workarounds (the
  `CLAUDE.md` import bridge and the `.claude/skills` symlink) exist solely for it, and both must survive every update.
- Kilo Code unified all clients (VS Code extension, JetBrains, CLI) onto `kilo.jsonc` with the `mcp` key. The old
  `.kilocode/mcp.json` (key `mcpServers`, `streamable-http`) is legacy; the repo ships only the `kilo.jsonc` template
  now. Kilo also introduced a newer `.kilo/` config directory that supersedes `.kilocode/`; the repo still targets
  `.kilocode/`, which remains backward-compatible.
- Codex only loads a project `.codex/` layer (hooks and MCP) after the project is trusted, so a fresh clone runs the
  preflight hook only once the user approves it.
- GitHub Copilot ships four surfaces (VS Code, JetBrains, CLI, cloud agent) that differ on hooks and MCP. Read the MCP
  table by surface, not by agent.
- The OpenCode and Kilo preflight adapters ride the still-experimental `chat.system.transform` hook. There is an open
  upstream report that the mutation can be silently dropped at runtime, so treat per-turn injection on those two as
  best-effort until the hook stabilises.
