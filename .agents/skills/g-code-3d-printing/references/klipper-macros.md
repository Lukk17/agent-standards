# Klipper Macros

What changes when the printer runs Klipper: complex sequences live in Jinja2 macros in `printer.cfg`, and the slicer only calls them. The rules that hold on every firmware are in [SKILL.md](../SKILL.md) and [start-and-end-gcode.md](start-and-end-gcode.md). The `SET_PRESSURE_ADVANCE` and `TOOL_CHANGE` rules are in [calibration-and-profiles.md](calibration-and-profiles.md).

---

### Klipper macros over raw sequences

On Klipper, tool changes, filament runout, and mesh levelling go through pre-configured Jinja2 macros, so the logic lives in `printer.cfg` under version control rather than being regenerated by every slicer export.

Pass:

```gcode
START_PRINT BED_TEMP=60 EXTRUDER_TEMP=215
```

Fail:

```gcode
M190 S60
M109 S215
G28
BED_MESH_CALIBRATE
G1 X1 Y20 Z0.3 F5000
```

---

### The START_PRINT macro body

The start sequence, home, heat to the real target, level, purge outside the part, then print, is the body of the `START_PRINT` macro in `printer.cfg`, and the slicer start G-code stays the single `START_PRINT` call shown above. The mesh loads after the heat, because the bed changes shape as it warms.

Pass, a complete `START_PRINT` macro body for a 220 x 220 bed:

```gcode
G90
M83
M140 S{params.BED_TEMP}
M104 S{params.EXTRUDER_TEMP}
G28
M190 S{params.BED_TEMP}
M109 S{params.EXTRUDER_TEMP}
BED_MESH_PROFILE LOAD=default
G92 E0
G1 Z5 F600
G1 X1.0 Y20 Z0.3 F5000
G1 E10 F300
G1 X1.0 Y180 E25 F1500
G1 X1.4 Y180 Z0.3 F5000
G1 X1.4 Y20 E40 F1500
G92 E0
G1 Z2 F3000
```

The matching end sequence is in [start-and-end-gcode.md](start-and-end-gcode.md#end-g-code).

### PID tuning

Klipper has no `M303`: the standard commands listed on https://www.klipper3d.org/G-Codes.html do not include it, and the page says "It is not a goal to support every possible G-Code command". Tune the hotend with the extended command before committing a new filament profile, as https://www.klipper3d.org/Config_checks.html shows:

```gcode
PID_CALIBRATE HEATER=extruder TARGET=<temp>
```

The same page says to run `SAVE_CONFIG` when the test completes, which writes the new PID settings to `printer.cfg`.
